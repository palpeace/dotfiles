# 読める日本語で書く

読み手は一度しか読まない。読み返させたら失敗である。

## どれを読むか

| 書くもの                             | 読む場所                                                  |
| ------------------------------------ | --------------------------------------------------------- |
| 設計文書・README・ADR・記事・解説    | `references/document.md`                                  |
| コミット・Issue・PR説明・レビュー    | `references/short-forms.md`                               |
| 人の書いた文を直す（推敲・リライト） | `references/rewrite.md`                                   |
| 書き上げたものの点検                 | `references/ng-phrases.md`（長文は `scripts/` の3本）     |

## 共通の3原則

1. 答えを先に置く。最初の1文で読み手が判断できるようにし、経緯・前置き・確認したことの列挙は後ろへ回す。問いに答えるなら、まず是か非かを書く。
2. 同じ命題を二度書かない。言い換えの反復、直後の要約、締めの決め台詞はどれも新しい命題を運んでいない。
3. 確認した事実と推測を書き分ける。確認していないことを、確認したように滑らかに書かない。

## 文の作り

読み手が詰まる文は、たいてい何かを隠している。隠し方は4つあり、`references/ng-phrases.md` がその分類である。

- 一文一命題。切る理由は長さではなく命題の数である。「〜し、〜のため、〜となっており」で2つ以上の命題を連ねた文は切り、前後の関係（理由・手段・順序・対比）を後ろの文の頭の接続語で残す。目的が文末の結論にかかる文（「〜するために〜を使う」）は、切ると何のための何かが読めなくなるので、切らずに語順を直す。
- 主体を書く。「〜が求められる」「対応されていない」は誰の作業かを隠す。無生物を主語にした他動詞（「この設計は柔軟性を提供する」）も同じで、「この設計なら、後から実装を差し替えられる」と書く。道具に意志を持たせる擬人化（「ログが語る」）も直す。道具の働きを述べる文（「このツールはログを集める」）は残す。
- 比喩の動詞を使わない。作業や判断を「効く」「壊れる」「倒す」「潰す」「溶かす」で言うと、何が起きたか・何を選んだかが消える。ふだんの動詞に戻し、「地味に」「〜てしまった」のような含みは別の語で残す。AIが広まる前から人の文章にある慣用句（「骨が折れる」「手を焼く」）は残す。
- 1語1義にする。同じものは同じ語で呼び、1つの語は1つの意味にだけ使う。意味の広い動詞（確認する・対応する・検討する・調整する）は、起きたことの動詞（見た・直した・比べた）に替える。
- 数と条件を書く。「適切に」「大幅に」「いくつか」は、読み手が好きな数に置き換えられる。その数で判断されても文句は言えない。
- 検証していないことは、していないと書く。「問題ありません」は、何を見たのかを隠したまま確認済みとして読まれる。
- 根拠で確定していることは言い切る。逆に、未確認の可能性・仮定・相手の疑念を表す「かもしれない」は残す。断定へ機械的に直すと、確認していないことを確認したと書くことになる。
- 文末は文書の立場で決める。勧め（読み手に頼む）・決まり（手順と規則）・説明（事実と考え）のどれかを先に1つ選び、文末をそれにそろえる。日本語は主語を省くので、誰が動くのか、決まりか勧めかを伝えるのは文末である。
- 定型の冗長は機械的に置き換える。「〜を行う」は「〜する」、「〜することが可能である」は「〜できる」、イ形容詞＋です（「難しいです」）は文を続けるか「〜である」で受ける。

## 人の文を直すとき

主張・比重・言い切りの強さ・文の働き（評価・説明・依頼・予定）の4つは変えない。変えてよいのは、それを運ぶ語と語順と文の切れ目と装飾である。言い切りの強さを変えてよいのは、根拠を自分で確かめたときだけである。元に無い主体・数・条件・例は足さず、足りない情報は本文で補わずに書き手への問いとして返す。読みやすくするために意味を動かすと、書き手が言っていないことを書き手の名前で出すことになる。判断の手順は `references/rewrite.md` にある。

## 装飾

| 道具               | 使ってよい条件                                                                   |
| ------------------ | -------------------------------------------------------------------------------- |
| 箇条書き           | 並列の項目が3つ以上あり、順序に意味がない。2つ以下は文で書く                     |
| 箇条書きの各項     | 主語と述語のある1文。体言止めの断片や「太字のラベル: 説明」を並べない。1項が3行を超えたら段落にする |
| 見出し             | その節が答える問いになっている。「概要」「その他」にしない                       |
| 表                 | 2軸（項目 × 属性）のデータである。散文の代わりに使わない。1列の表を作らない      |
| 太字               | 誤読を防ぐ否定と、判断が要る点だけ                                               |
| コードブロック     | そのままコピーして実行・貼り付けできる単位である                                 |
| 記号               | 文末のコロン・ダッシュ・言い換えだけのカッコを使わない。和欧文の間の空白は文書の中でそろえる |
| 絵文字・チェックマーク | 使わない                                                                     |

## 書き上げたら

1. 冒頭1文（文書なら最初の3行）だけを読む。それで答えになっていなければ、順序から書き直す。
2. 各段落の1文目を縦に読む。同じ主題が2回出ていれば、片方を消す。
3. 装飾の表を上から当てる。条件を満たさない箇条書き・見出し・表・太字を外す。
4. 答え・根拠・主体・量の4つを隠していないか見る（分類と直し方は `references/ng-phrases.md`）。
5. 長い文書には `scripts/check-ng.sh`（隠している語）と `scripts/measure.py`（文の長さ・読点・太字・箇条書き・文末と表記の揃いを数で出す）を当てる。人の文を直したら、`scripts/compare.py 元 直し` で文末・言い回し・数・語の増減を見る。出るのは候補で、直すかどうかは自分で決める。
6. 削る。行数が減らなかったら、削り方が足りない。
