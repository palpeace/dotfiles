# 隠している語を見つけて、直す

使わない語を暗記する必要はない。**その語が何を隠しているか**で4つに分かれ、直し方も分類ごとに決まる。
5つ目だけは何も隠さず、行を増やすだけの型である。

全パターンの機械可読な一覧は `scripts/ng-patterns.tsv`。長い文書には次を当てる。

```
~/.claude/skills/readable-japanese/scripts/check-ng.sh docs/design.md        # ほぼ常に誤りの型だけ
~/.claude/skills/readable-japanese/scripts/check-ng.sh --all docs/design.md  # 候補も含めて出す
~/.claude/skills/readable-japanese/scripts/measure.py docs/design.md         # 形を数で測る
~/.claude/skills/readable-japanese/scripts/compare.py before.md after.md     # 直す前と後を比べる
```

`hard` はほぼ常に誤り、`soft` は文脈で判断する候補である。拾えるのは文字列の一致だけなので、判断は必ず自分で行う。

`measure.py` は語ではなく形を見て、次の箇所を出す。長さと読点はカッコの中を数えない。

- 90字を超える文と、読点が4つ以上ある文
- 本文1000字あたり4つを超える太字と、本文の行の半分を超える箇条書き（本文が400字に満たない文書では見ない）
- 敬体と常体の混ざり、和欧文の空白の不揃い、句読点の横の空白
- 文末のコロン、予告だけの文、「太字のラベル: 説明」の項、段落の頭で前を指す「これ」「それ」

数は、超えたら読み直す目安であって、超えたら誤りという線ではない。規則の一覧のように項がすべて並列なら、箇条書きが半分を超えてよい。数を下げること自体を目的にすると、決め台詞の短文を差し込むような、別の読みにくさが生まれる。

`compare.py` は、人の文を直したあとに使う（`references/rewrite.md` の7）。

## 1. 答えを隠す

読み手が最初に探しているのは答えである。その手前に置いた語は、全部が障害物になる。

| 隠している語 | 直し方 |
| ------------ | ------ |
| 「承知しました」「了解しました」 | 消す。答えから始める |
| 「以下に説明します」「まず〜を確認しました」 | 予告と経過を消す。結果を1文目に置く |
| 「〜については、〜です」 | 主題の再提示を落とし、述語から書く |
| 「まとめると」「要するに」 | 直前の言い換えなら、その文ごと消す |
| 「結論から言うと」 | 消す。結論を1文目に置けば、前置きは要らない |
| 「重要なのは」「大事なのは」 | 評価を述語に移す（「〜が重要だ」）。評価でなく前置きなら消す |
| 「押さえる点は3つある」「次のとおりである」 | 予告だけの文。予告の重みを1つ目の中身の文に移す |
| 「いかがでしたか」「参考になれば幸いです」 | 消す。最後の命題で終える |
| 「何かご不明な点があれば」「お気軽に」 | 消す。判断が要るなら、その問いだけを書く |

悪い例: 「承知しました。まずテストの状況を確認しました。以下に結果を説明します。3件が失敗していました。」
良い例: 「テストが3件失敗しています。」

## 2. 根拠を隠す

一番害が大きい型である。読み手は「確認済み」として受け取り、後で1件でも外れると文書ごと信用を失う。

| 隠している語 | 直し方 |
| ------------ | ------ |
| 「正常に完了しました」「問題ありません」 | 何を実行して何を見たかを書く（「48件のテストが通った」） |
| 「修正しました」だけ | 何がどう変わったかを書く。差分の説明ではなく、挙動の変化 |
| 「一般的には」「ベストプラクティスでは」 | 出所を書く。書けないなら、自分の判断として書く |
| 「〜と思われます」「〜と考えられます」 | 根拠があるなら言い切る。無いなら「未確認」と書く |
| 「シンプルに」「クリーンに」「きれいに」 | 自分の成果への評価を消す。読み手が判断する |
| 「知見」「示唆」「洞察」 | 中身を1文で書く。書けないなら、その行は要らない |
| 「解像度を上げる」「腹落ちする」「手触り」 | 何をどこまで調べたか、何が分かったかを書く |
| 「〜と言えるでしょう」「〜に他ならない」 | 根拠があるなら言い切る。元が推量なら推量のまま、ラベルだけを外す |

悪い例: 「認証周りをリファクタリングしてクリーンにしました。動作は問題ありません。」
良い例: 「セッション検証を1関数に寄せました。テストは48件通り、期限切れの挙動だけ手で確認しています。」

## 3. 主体を隠す

誰が何をするのかが消えると、読み手は自分の担当かどうかを判断できない。
比喩の動詞と擬人化もこの型に入る。何が起きたか、誰が何を選んだかを、比喩が隠すからである。

| 隠している語 | 直し方 |
| ------------ | ------ |
| 「〜が求められる」「〜が期待される」 | 誰が要求しているのかを書く |
| 「〜する必要がある」（誰の作業か不明） | 主語を立てる（「呼び出し側が〜する」） |
| 「対応されていない」「検討されていない」 | 誰が対応していないのかを書く。不明なら不明と書く |
| 「この設計は柔軟性を提供する」 | 無生物を主語にした他動詞をやめ、何ができるようになるかを書く |
| 「実装が〜を許す」「仕様が〜を要求する」 | 人か処理を主体に戻す |
| 「コードが語る」「数字が教えてくれる」 | 擬人化をやめ、どこに何が書いてあるか、誰が何を読み取ったかを書く |
| 「静かに壊れる」「黙って捨てられる」 | 何がどうおかしくなるかを書く。気づけないという含みは「気づかないうちに」で残す |
| 「地味に効く」「〜のほうが効いた」 | 何がどう良くなったかを書く。「地味に」の含みは「目立たないが」で残す |
| 「安全側に倒す」「1つずつ潰す」「時間を溶かす」 | 何を優先するか、何を直すか、何にどれだけかかったかを、ふだんの動詞で書く |
| 「落とし穴」「〜という事故」 | 何を見落とすと何が起きるかを書く |

悪い例: 「エラー処理の統一が求められるが、現状では対応されていない。」
良い例: 「エラー処理は呼び出し側ごとにばらばらで、統一する担当を決めていない。」

悪い例: 「並び順の前提が静かに壊れ、集計が黙って欠ける。」
良い例: 「並び順が入れ替わっても処理は止まらず、集計から行が欠けたことに気づけない。」

## 4. 量と範囲を隠す

数の入らない評価は、読み手が好きな数に置き換える。その数で判断されても文句は言えない。

| 隠している語 | 直し方 |
| ------------ | ------ |
| 「適切に」「しっかりと」「きちんと」 | 消す。条件か数で書く |
| 「必要に応じて」「一定の」「所定の」 | 条件を書く（「10件を超えたら」） |
| 「大幅に」「かなり」「非常に」「極めて」 | 数を書く。無いなら形容を消す |
| 「いくつかの」「多くの場合」 | 件数と、数えた範囲を書く |
| 「ほぼ」「概ね」（検証の話で） | 何件のうち何件かを書く |

悪い例: 「多くのケースで大幅に速くなりました。」
良い例: 「10件の入力のうち8件で 1.2 秒から 0.3 秒になりました。残り2件は変わりません。」

## 5. 行を増やすだけの型

意味は隠していないが、読む時間だけを取る。ここは機械的に置き換えられる。

| 型 | 直し方 |
| -- | ------ |
| 「〜を行う」 | 「〜する」 |
| 「〜することが可能である」「〜することができます」 | 「〜できる」 |
| 「〜という形で」「〜という点で」「〜の観点から」 | 格助詞1つで足りることが多い |
| 「〜させていただきます」 | 「〜します」 |
| 「〜していく」「〜してまいります」 | 「〜する」 |
| 「難しいです」「多いです」（イ形容詞＋です） | 「〜は難しく、…」と文を続けるか「〜である」で受ける |
| 「単なるAではなく、B」 | 誰も言っていないAを退ける演出なら、Aを外してBを肯定で書く |
| ダッシュ（——）で挟んだ補足 | 助詞か句点でつなぐ |
| 文末のコロン（「理由は次のとおり:」） | 句点で閉じるか、前置きを消して中身から書く |
| 言い換えだけのカッコ（「設定ファイル（コンフィグ）」） | 外す。略語の定義は初出に1回だけ置く |
| 「**ラベル**: 説明」の箇条書き | ラベルを主語にした1文にする |
| 絵文字・チェックマーク | 使わない。状態は語で書く |

## 残していいもの

弱い述語や反復には、削ってはいけないものがある。次は対象外である。

- 未確認の可能性・仮定・相手が抱きそうな疑念を表す「かもしれない」「だろう」。断定へ機械的に直すと、分類2（根拠を隠す）に変わる。
- 条件と限定（「〜が成り立つときに限り」「10件までなら」）。長くなるが、これを削ると分類4になる。
- 定義の直後に置く適用条件。同じ話題の繰り返しではなく、別の命題である。
- 並列の項が同じ地位であることを示す枠語の反復（各項の「〜の場合」など）。
- 文のつながりを作る接続（「しかし」「一方で」）。前後の何と何をつないでいるかを言えるものに限る。
- 誤読を正す否定対比。Aだと思われがちなところをBと言い直す「AではなくB」は、否定が命題を運んでいる。
- 文字どおりの意味の動詞（「時計が壊れる」「氷を溶かす」）と、AIが広まる前から人の文章にある慣用句（「骨が折れる」「主導権を握る」）。
- 道具の働きを述べる無生物主語（「このツールはログを集める」）と、順を追う手順の「まず〜する」。
