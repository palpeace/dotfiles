# agy への委譲

Claude Code のトークン消費は「実装そのもの」ではなく「実装の過程で読んだもの・出力したもの」が文脈に積み上がることで膨らむ。判断はClaudeが持ち、大量読解・機械的変換・緑化ループは `agy`（Antigravity CLI / Gemini Flash）へ渡す。

## いつ使うか

以下の**両方**を満たす作業だけを委譲する。判断に迷ったら委譲しない。

- 読む/書く量が多いが、判断基準が機械的に書ける（rename・整形・移行・横断調査の列挙・テスト/lintの緑化）
- 結果を**機械的に検証できる**（ファイル差分・終了コード・テスト結果。「読んで良し悪しを判断する」しかないなら委譲しない）

**渡さないもの**: 設計判断・規約変更・ユーザーとの対話・不可逆操作（コミット・push・削除・force系）、複数の情報源をどう1つに統合するかの判断（機械的な正解が無く検証できない）。

## 使い方

```bash
~/.local/bin/agy-run <workspace-dir> <task-spec-file> --model <m1[,m2,...]> [--schema <file>] [--timeout 20m]
```

- `<task-spec-file>` に規範＋指示＋出力形式を書く。**agyは印刷モードでAGENTS.md/GEMINI.mdを読まない**ため、必要な規範はこのファイルに毎回同梱する
- `--model` に既定値はない。どのモデルを何番目に使うかはタスク／リポジトリ側の可変値であり、このskillは持たない（優先順の権威はリポジトリ側に置く）
- 標準出力に流れるのは結果ディレクトリのパスだけ。**そのディレクトリの中身を全部読まない** — `jq` で必要なフィールドだけ取り出す
- 詳しいオプションは `agy-run --help`

## 受け入れは自分で検証する

**agyの自己申告を成否の判定に使わない。** 権限で拒否された時でも空応答ではなく成功したかのような応答を返すことがある。受け入れは必ずファイルの存在・`git diff`・テスト・lintなど呼び出し側の機械検証で行う。

## 権限

`agy` の headless 実行はデフォルトで `read_file` すら拒否される。`~/.gemini/antigravity-cli/settings.json` の `permissions.allow` にワークスペースのパスを許可する必要がある。権限はグローバル設定にしか書けない（プロジェクト直下の設定は無視される）ため、破壊的なコマンド（`git commit` / `git push` / `git reset` / `rm` 等）を許可リストに入れないこと。
